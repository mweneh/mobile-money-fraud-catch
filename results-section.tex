\section{Results}
This section presents the experimental results from training and evaluating machine learning algorithms on the mobile money fraud detection task. The analysis utilised a dataset of mobile money transactions, which was processed and split into training, validation, and testing sets to ensure robust model evaluation.

\subsection{Data Understanding}

As shown in Figure~\ref{fig:class_distribution}, the dataset exhibited severe class imbalance, with fraudulent transactions representing approximately 0.2\% of all labelled cases. Of the 95,662 entries in the training set, 95,469 were legitimate (class 0), and 193 were fraudulent (class 1), yielding a fraud rate of 0.202\%. The validation set, created via a stratified 80-20 split to preserve the minority-class distribution, comprised 23,916 transactions, of which 23,868 were legitimate, and 48 were fraudulent. The test set included 45,019 unlabeled transactions reserved for final model evaluation.

\subsection{Data Preparation; Experimental Setup}
Data quality checks confirmed that the training data contained no missing values and no duplicate transaction identifiers. To ensure robustness and generalizability of results, all models were trained using 5-fold stratified cross-validation. To get the best out of our data, we engineered features from interactions, ratios and temporal flags. Additionally, account-level behavioural statistics were computed to capture deviations from typical user behaviour. Finally, scaling was applied using StandardScaler for linear models such as Logistic Regression. We configured our algorithms to assign higher misclassification penalties to fraud cases through class weighting. This configuration forces the models to focus on the minority class during training, essentially telling them that missing fraud is more costly than misclassifying the occasional legitimate transaction. Common class weighting strategies such as (\texttt{class\_weight='balanced'} and \texttt{scale\_pos\_weight})were employed to address the severe class imbalance challenge. Hyperparameters for the LightGBM model were tuned using random Search, resulting in the following optimal configuration: \texttt{learning\_rate=0.01}, \texttt{n\_estimators=700}, \texttt{num\_leaves=50}, and \texttt{subsample=0.9}.

\subsection{Machine Learning Modeling}

Five models were trained and compared: LightGBM, Random Forest, XGBoost, Logistic Regression, and LinearSVC. For the baseline comparison, models were trained with imbalance handling (\texttt{class\_weight='balanced'} for scikit-learn models, and \texttt{scale\_pos\_weight} for XGBoost) and evaluated on the validation split using the default threshold (0.5).
Table~\ref{tab:initial_comparison} presents the initial performance metrics for the five machine learning algorithms. The models were evaluated using a default classification threshold of 0.5 on the validation data. Given the highly imbalanced nature of our data, the Area Under the Precision-Recall Curve (PR-AUC) and F1 scores were selected as the primary metrics for model selection. LightGBM achieved the strongest PR-AUC (0.9273), indicating the most favourable precision--recall behaviour under extreme class imbalance. While Random Forest achieved a slightly higher F1 at the default threshold, its PR-AUC was lower, implying weaker performance across operating points. XGBoost yielded a ROC-AUC of 0.9988 but showed notably lower PR-AUC (0.5469), with an F1-score of 0.5564, precision of 0.2115, and recall of 0.9583. Logistic Regression achieved the highest ROC-AUC (0.9974) but demonstrated moderate PR-AUC (0.5885), with an F1-score of 0.3439 and a recall of 0.9167.
Despite LightGBM's superior overall performance metrics, the baseline F1-score of 0.7907 indicated a high false positive rate at the default threshold, necessitating threshold optimisation to improve practical deployment viability.

\subsection{Threshold Optimization }

We conducted a Precision-Recall Curve analysis to identify the optimal decision threshold that maximises F1. In the optimisation process, trade-offs between precision and recall were analysed across the full range of probability scores. For LightGBM, our optimisation process yielded substantial performance improvements by adjusting the threshold from the default 0.50 to 1.00. The threshold adjustment resulted in a 14\% increase in the model's F1-score, from 0.7907 to 0.9067. Subsequently, the new threshold led to a 171\% increase in precision from 0.3684 to approximately 1.0000 and a modest decrease in recall from 0.8974 to 0.7850. Notably, an optimal threshold of 1.00 represents a strict high-confidence boundary, at which precision estimates approach unity for a small subset of transactions. Such high confidence levels indicate that the LightGBM model not only achieves near-zero false positives but also maintains acceptable recall levels. Figure \ref{fig:threshold_optimization} illustrates that while recall decreases slightly at higher thresholds, precision increases dramatically, driving the maximised F1-score.

\subsubsection{SMOTE Integration}

To achieve training-set rebalancing,  SMOTE was applied to the scaled training subset, transforming the training distribution from 76,529 samples with 154 fraud cases to a balanced synthetic dataset (152,750 samples, 50/50 class balance). Table \ref{tab:model-comparison-grouped} shows the combined comparison between class-weighted training and SMOTE-based training. SMOTE improved PR-AUC for gradient-boosting (XGBoost achieved 0.9411, the highest PR-AUC observed), indicating improved ranking and retrieval of the minority class across thresholds. However, the class-weighted LightGBM achieved the strongest F1 after threshold tuning (0.9067), making it a strong candidate for operational settings where a balanced precision--recall trade-off is desired.

\subsection{Feature Importance}
Feature importance analysis (Figure~\ref{fig:feature-importance}) from the LightGBM model shows that Amount is by far the most important predictor, highlighting transaction size as the primary driver of model decisions, followed by Value, which also contributes substantially. A second tier of importance is dominated by account-level behavioural features such as $ Account_TxnCount Account_StdAmount, Account_AvgAmount, Account_MinAmount, and Account_MaxAmount, $ indicating that deviations from an account’s typical transaction patterns are critical for identifying anomalous activity. Transformed variables such as LogAmount further reinforce the role of transaction magnitude across scales. Temporal indicators, including IsBusinessHour and IsWeekend, along with contextual features such as PricingStrategy, provide additional but comparatively weaker predictive power.

\subsection{Final Model Evaluation and Deployment}

The optimised LightGBM model was retrained on the whole training dataset and applied to the unseen Test Set ($n=45{,}019$). The final model identified \textbf{53 high-risk transactions}, representing 0.118\% of the test volume. This new rate closely aligns with the training fraud rate of 0.2\%, suggesting excellent calibration. Additionally, the final model achieves a significant reduction in type I errors (false positives).To support operational use, the same scoring logic can be executed in an interactive interface (\texttt{https://mweneh-mobile-money-fraud-catch-app-7opctk.streamlit.app/}), enabling probability-based decisions and threshold-sensitive routing.
